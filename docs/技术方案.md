# 课题组财务管理系统 - 技术方案

## 1. 技术选型

### 1.1 整体架构
```
┌─────────────────────────────────────────────────┐
│                   Next.js 全栈应用               │
├─────────────────┬───────────────────────────────┤
│   前端 (React)  │        后端 (API Routes)      │
│   - 页面组件     │        - RESTful API          │
│   - 状态管理     │        - 业务逻辑             │
│   - UI组件库     │        - 数据验证             │
├─────────────────┴───────────────────────────────┤
│              数据层 (Prisma ORM)                 │
├─────────────────────────────────────────────────┤
│              数据库 (SQLite → PostgreSQL)        │
└─────────────────────────────────────────────────┘
```

### 1.2 技术栈详情

| 层级 | 技术 | 理由 |
|------|------|------|
| 框架 | Next.js 14 | 全栈框架，开发效率高，部署简单 |
| 前端 | React 18 + TypeScript | 类型安全，生态丰富 |
| UI库 | shadcn/ui + Tailwind CSS | 美观、可定制、无需从零写样式 |
| 状态 | Zustand | 轻量、简单 |
| 表单 | React Hook Form + Zod | 表单处理+验证 |
| 后端 | Next.js API Routes | 无需单独后端服务 |
| ORM | Prisma | 类型安全，自动生成类型 |
| 数据库 | SQLite（开发）→ PostgreSQL（生产） | 零配置开发，生产可靠 |
| 认证 | NextAuth.js | 成熟方案 |
| 文件 | 本地存储 → 云存储（可选） | 简单起步 |
| 部署 | Vercel | 免费，一键部署，自动CI/CD |

### 1.3 为什么选这个栈？

**简单**：
- 一套代码，前后端都搞定
- 不用学两个框架
- Vercel一键部署，不用折腾服务器

**免费**：
- Vercel免费额度足够课题组使用
- Supabase免费PostgreSQL
- 零成本上线

**易维护**：
- TypeScript类型安全，减少bug
- 代码量少，结构清晰
- 社区活跃，问题好搜

### 2.2 数据模型

```prisma
// 用户
model User {
  id        String   @id @default(cuid())
  name      String
  email     String   @unique
  password  String
  role      Role     @default(STUDENT)
  expenses  Expense[]
  created   DateTime @default(now())
  updated  DateTime @updatedAt
}

enum Role {
  STUDENT       // 学生
  ASSISTANT     // 财务助理
  SUPERVISOR    // 导师
  ADMIN         // 管理员
}

// 经费项目
model Fund {
  id          String   @id @default(cuid())
  name        String
  code        String   @unique
  source      String   // 纵向/横向
  totalAmount Float
  usedAmount  Float    @default(0)
  startDate   DateTime
  endDate     DateTime
  status      FundStatus @default(ACTIVE)
  expenses    Expense[]
  created     DateTime @default(now())
  updated     DateTime @updatedAt
}

// 报销单
model Expense {
  id          String       @id @default(cuid())
  title       String
  type        ExpenseType
  amount      Float
  description String?
  status      ExpenseStatus @default(DRAFT)
  fundId      String
  fund        Fund         @relation(fields: [fundId], references: [id])
  applicantId String
  applicant   User         @relation(fields: [applicantId], references: [id])
  invoices    Invoice[]
  approvals   Approval[]
  created     DateTime     @default(now())
  updated     DateTime     @updatedAt
}

enum ExpenseType {
  TRAVEL      // 差旅
  PURCHASE    // 采购
  PUBLICATION // 版面费
  OTHER       // 其他
}

enum ExpenseStatus {
  DRAFT       // 草稿
  PENDING     // 待审批
  APPROVED    // 审批通过
  PROCESSING  // 财务处理中
  ACCEPTED    // 已受理
  COMPLETED   // 已完成
  REJECTED    // 已驳回
}

// 发票
model Invoice {
  id           String   @id @default(cuid())
  code        String   // 发票代码
  number      String   // 发票号码
  issueDate   DateTime // 开票日期
  seller      String   // 销售方
  amount      Float    // 金额
  taxAmount   Float    // 税额
  totalAmount Float    // 价税合计
  type        String   // 类型
  expenseId   String?
  expense     Expense? @relation(fields: [expenseId], references: [id])
  filePath    String?  // 电子发票文件路径
  isDuplicate Boolean  @default(false)
  created     DateTime @default(now())
  @@unique([code, number]) // 防重
}

// 审批记录
model Approval {
  id         String   @id @default(cuid())
  expenseId  String
  expense    Expense  @relation(fields: [expenseId], references: [id])
  approverId String
  action     String   // approve/reject
  comment    String?
  created    DateTime @default(now())
}

// 采购单
model Purchase {
  id          String        @id @default(cuid())
  title       String
  type        String        // 设备/耗材/服务
  amount      Float
  description String?
  status      PurchaseStatus @default(PENDING)
  applicantId String
  created     DateTime      @default(now())
  updated     DateTime      @updatedAt
}

enum PurchaseStatus {
  PENDING    // 待审批
  APPROVED   // 已审批
  ORDERED    // 已下单
  RECEIVED   // 已到货
  COMPLETED  // 已完成
}
```

## 3. API设计

### 3.1 认证相关
```
POST   /api/auth/register    # 注册
POST   /api/auth/login       # 登录
POST   /api/auth/logout      # 登出
GET    /api/auth/session     # 获取当前用户
```

### 3.2 经费管理
```
GET    /api/funds            # 经费列表
POST   /api/funds            # 新增经费
GET    /api/funds/:id        # 经费详情
PUT    /api/funds/:id        # 更新经费
DELETE /api/funds/:id        # 删除经费
GET    /api/funds/stats      # 经费统计
```

### 3.3 报销管理
```
GET    /api/expenses         # 报销列表（支持筛选）
POST   /api/expenses         # 新增报销
GET    /api/expenses/:id     # 报销详情
PUT    /api/expenses/:id     # 更新报销
DELETE /api/expenses/:id     # 删除报销
POST   /api/expenses/:id/approve  # 审批通过
POST   /api/expenses/:id/reject   # 审批驳回
GET    /api/expenses/stats   # 报销统计
```

### 3.4 发票管理
```
GET    /api/invoices        # 发票列表
POST   /api/invoices        # 新增发票
GET    /api/invoices/:id    # 发票详情
POST   /api/invoices/check  # 发票查重
POST   /api/invoices/upload # 上传发票图片
```

## 5. 部署方案

### 5.1 开发环境
```bash
# 安装依赖
npm install

# 配置数据库
npx prisma db push

# 启动开发服务
npm run dev
```

### 5.2 生产部署

**方案一：Vercel（推荐）**
1. 推送代码到GitHub
2. Vercel导入项目
3. 配置环境变量
4. 自动部署

**方案二：自有服务器**
1. 安装Docker
2. 构建镜像
3. 运行容器

### 5.3 数据库方案
- **开发**：本地SQLite（无需配置）
- **生产**：
  - 方案A：Vercel Postgres（与Vercel集成）
  - 方案B：Supabase（免费PostgreSQL）
